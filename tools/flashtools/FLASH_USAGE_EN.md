# Flash Tool Usage Guide

## Overview

`download.py` is a unified flashing tool for Lierda OpenCPU devices. It supports both full firmware flash and app-only flash. Currently only supports Windows.

## Requirements

- Python 3.6+
- Python dependencies: `pyserial` (required), `py7zr` (optional, for .7z extraction)
  - Install command: `pip install pyserial` or `pip install pyserial py7zr`
- FlashToolCLI tool (supports .zip or .7z format, automatically extracted)
  - .7z format uses the project's built-in `tools/7z/7z.exe` tool first
  - Falls back to py7zr module if 7z.exe is not found
- USB or UART connection to target device

## Command Line Usage

### Basic Syntax

```bash
python download.py <pkg_path> --type <full|app> --mode <usb|uart> [--port <PORT>] [--erase]
```

### Required Parameters

- `pkg_path`: Path to the `.binpkg` file (required)
- `--type`: Flash type, must be `full` or `app` (required)
- `--mode`: Download mode, `usb` or `uart` (required)

### Optional Parameters

- `--port`: Specify COM port (e.g., COM7). Auto-detect if not specified in USB mode. If module firmware is abnormal and USB AT port cannot be enumerated, you need to manually enter boot mode and specify the flash port (pull boot pin high and reset the module to enter).
- `--erase`: Perform full partition erase before flashing (full flash only, will erase all partitions except RF calibration area, including filesystem and system configuration areas).

### Examples

**Full flash - USB mode with auto-detect:**

```bash
python download.py firmware.binpkg --type full --mode usb
```

**Full flash - USB mode with specific port:**

```bash
python download.py firmware.binpkg --type full --mode usb --port COM7
```

**Full flash - UART mode (port required):**

```bash
python download.py firmware.binpkg --type full --mode uart --port COM7
```

**App-only flash:**

```bash
python download.py firmware.binpkg --type app --mode usb --port COM7
```

**Full flash with partition erase:**

```bash
python download.py firmware.binpkg --type full --mode usb --port COM7 --erase
```

## Using with Makefile

### Required Parameters

Both `pkg` and `type` parameters are **required**:

```bash
make burn pkg=<file.binpkg> type=<full|app> mode=<usb|uart> [port=<PORT>] [erase=1]
```

### Makefile Examples

**Full flash - USB mode:**

```bash
make burn pkg=firmware.binpkg type=full mode=usb
make burn pkg=firmware.binpkg type=full mode=usb port=COM7
```

**App-only flash:**

```bash
make burn pkg=firmware.binpkg type=app mode=usb port=COM7
```

**Full flash - UART mode:**

```bash
make burn pkg=firmware.binpkg type=full mode=uart port=COM7
```

**With chip erase:**

```bash
make burn pkg=firmware.binpkg type=full mode=usb port=COM7 erase=1
```

### Using with build.bat

```bash
.\build.bat burn pkg=gccout\app\app_NT26F6D0_01.binpkg type=full mode=usb
.\build.bat burn pkg=gccout\app\app_NT26F6D0_01.binpkg type=app mode=usb port=COM7
```

## Flash Type Details

### Full Flash (`--type full`)

Complete firmware flash including all partitions:

1. Extracts package with `pkg2img`
2. Detects and probes device
3. Configures product settings
4. Burns all images (if erase parameter is configured, erase operation will be performed)
5. System reset

### App Flash (`--type app`)

Flash only the application binary:

1. Extracts package with `pkg2img`
2. Reads `imagedata.json` to get PKGFLXAPP info
3. Probes device
4. Erases app flash region
5. Burns app binary
6. System reset

**Note:** App flash requires `imagedata.json` generated by `pkg2img` command.

## Download Modes

### USB Mode (`--mode usb`)

- If device firmware is abnormal and USB AT port cannot be enumerated, manual operation is required to enter download mode
- Can auto-detect port if not specified
- Faster than UART mode

### UART Mode (`--mode uart`)

- Requires explicit port specification
- Uses serial communication
- Slower than USB mode

## Port Auto-Detection (USB Mode Only)

When `--port` is not specified in USB mode:

1. First searches for "Lierda At Port"
2. If not found, prompts user to enter download mode
3. Waits for "Lierda QDLoader Port" (10s timeout)

## Error Handling

### Common Errors

**Missing pkg parameter:**

```
ERROR: pkg parameter is required. Usage: make burn pkg=<file.binpkg> type=<full|app> mode=<usb|uart> [port=<PORT>]
```

**Missing type parameter:**

```
ERROR: type parameter is required. Usage: make burn pkg=<file.binpkg> type=<full|app> mode=<usb|uart> [port=<PORT>]
```

**Wrong file extension:**

```
ERROR: pkg file must end with .binpkg, got: firmware.bin
```

**Invalid type value:**

```
ERROR: type must be 'full' or 'app', got: partial
```

**Port detection failed:**

```
ERROR: Failed to detect Lierda QDLoader Port
Please check:
  1. Device is connected via USB
  2. Device drivers are installed
  3. Device is in download mode
```

**Solution:** Manually specify port with `--port COM7`

## Tips

1. **Always use `.binpkg` extension** - Other extensions are rejected
2. **Both pkg and type are required** - No auto-detection or defaults
3. **USB mode is recommended** - Faster and supports auto-detection
4. **Specify port for stability** - Auto-detection may fail in some environments
5. **UART mode requires port** - Port parameter is mandatory for UART mode
6. **Erase behavior** - By default, configuration and filesystem partitions are NOT erased. Use `--erase` flag to enable erasing. It's recommended to erase for:
   - First-time flashing
   - After partition layout changes
   - Note: Calibration NV partition is never erased, only config and filesystem partitions are affected
7. **App flash supports both modes** - Although `--type app` requires a `.binpkg` file, it only flashes the application partition, making it much faster than full flash
8. **Firmware compatibility** - The flashing firmware must match the actual hardware. Please check hardware model before flashing
