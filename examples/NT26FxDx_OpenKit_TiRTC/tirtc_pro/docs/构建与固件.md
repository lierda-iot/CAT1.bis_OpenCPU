## 构建配置

构建前在工程根目录 `Makefile` 中确认项目与底包参数：

```make
export PROJECT  ?= NT26FxDx_OpenKit_TiRTC
export MODEM    ?= NT26F6D0
export MODEMPKG ?= F6D_D
```

在 `examples/NT26FxDx_OpenKit_TiRTC/config` 中选择产品和构建模式：

```make
APP_VARIANT ?= pro
BUILD_MODE ?= full
```

完成配置后，在工程根目录执行：

```sh
make all
```

切换构建目标时，修改配置文件中的 `BUILD_MODE` 并再次执行 `make all`。Pro 支持以下模式：

| `BUILD_MODE` | 生成内容 | 主要输出 |
| --- | --- | --- |
| `full` | 正式应用包及含外置资源镜像的完整包 | `gccout/NT26FxDx_OpenKit_TiRTC/NT26FxDx_OpenKit_TiRTC_NT26F6D0_pro_app.binpkg` 和 `gccout/NT26FxDx_OpenKit_TiRTC/NT26FxDx_OpenKit_TiRTC_NT26F6D0_pro.binpkg` |
| `app` | 正式应用包 | `gccout/NT26FxDx_OpenKit_TiRTC/NT26FxDx_OpenKit_TiRTC_NT26F6D0_pro_app.binpkg` |
| `assets` | 临时资源安装器包 | `gccout/NT26FxDx_OpenKit_TiRTC/NT26FxDx_OpenKit_TiRTC_NT26F6D0_pro_assets.binpkg` |

这些包由当前工程直接生成。本文不假设存在独立发布目录，也不依赖其他仓库副本或旧批处理脚本。源码、构建脚本和工具位于当前完整 SDK 工程中。

## 烧录选择

首次烧录或更新外置 UI 资源时，使用两阶段流程：

1. 将 `BUILD_MODE` 设为 `assets`，执行 `make all`，全量下载生成的 `_pro_assets.binpkg`。
2. 启动设备，等待日志 `[assets14] INSTALL_OK`。若出现 `INSTALL_FAILED`，保留日志并先排查。
3. 将 `BUILD_MODE` 改为 `app`，再次执行 `make all`，全量下载生成的 `_pro_app.binpkg`。
4. 正常启动后确认 `[assets14] LOAD_OK`，检查界面资源。

资源安装器不会自动变成正式应用。必须等资源安装成功，再烧录正式应用。下载工具报告下载成功不等于设备已完成外置资源写入。

`BUILD_MODE=full` 生成的 `_pro.binpkg` 含有外置资源文件系统镜像。只有确认下载工具支持本板外置 Flash 写入时才使用该包；写入镜像会覆盖外置 Flash 上的文件。具体设备操作见[当前设备操作](当前设备操作.md#3-安装外置资源并烧录应用)。

全量下载可能影响设备内已有数据。烧录前备份需要保留的设置和文件，并按实际下载工具的擦除行为选择操作。若从不同底包版本迁移，确认待烧录包与本项目配置相符，不要只凭文件名或应用内部版本号判断兼容性。

## 资源包说明

Pro 正式应用从外置 Flash 读取 UI 资源。资源安装器负责把配套资源写入外置文件系统，并通过 `[assets14] INSTALL_OK` 报告安装完成；正常应用启动后通过 `[assets14] LOAD_OK` 报告资源加载成功。资源清单、安装行为和错误处理见[资源维护](../resource_store/README.md)。

资源安装器与正式应用必须来自同一份工程源码和兼容的构建配置。只更新正式应用不能补齐缺失或版本不匹配的外置资源。
