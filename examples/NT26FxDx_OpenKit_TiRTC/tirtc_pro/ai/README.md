# AI 对话与联系人呼叫

当前功能与云端配置集中在 [AI 呼叫配置篇](../docs/AI呼叫微信与设备配置详解.md)，操作见 [AI 对话](../docs/当前设备操作.md#ai)。本模块支持普通呼叫默认视频、显式 `audio/voice` 使用语音；最终转交原有 calls/UI 流程。

## 入口与生命周期

- `tirtc_ai_start_service()` 创建 96 KiB、优先级 13 的业务线程；重复启动不创建第二个实例。
- `tirtc_ai_action()` 接受 UI 的开始、停止和导航；0 仅表示受理。
- `tirtc_ai_publish()` 复制 AI 状态和字幕，工作线程自行调用；不要从小栈 GUI 周期调用大快照函数。
- 正式身份、时间、平台 API/MQTT、4G 和 runtime 就绪后才建连。凭据/网络代次变化使原请求失效。
- 获取 AI token、受管 WHIP、发送 `0x2100 start_session`，确认格式后进入对话。后台预备不能占用本应接受 LIVE 的空闲首页。
- 停止后禁止新媒体，发送结束、等待音频和连接安全释放。HOME/CLOCK/MENU/DIAGNOSTICS 可保留 AI；其他页面请求停止。

## 当前音频参数

以下以 `tirtc_ai.c` 常量为准，不沿用早期 120 ms ahead / 960 字节预缓冲参数。

| 项目 | 当前值 |
| --- | --- |
| 本机音频 | 16 kHz、单声道 PCM16；20 ms = 320 样本 = 640 PCM 字节 |
| 网络音频 | Opus / 16 kHz 单声道；上行 20 ms、目标 24 kbit/s、复杂度 3，编码字节数可变；下行按完整包解码为 16 kHz PCM |
| 上行 stream_id | 1 |
| 接收字节预算 | `AI_RX_BYTES=15360`，另限 96 包、30720 个 16 kHz 样本（1.92 秒），任一超限都丢整包 |
| 命令槽 | 3 × 4608 字节 |
| 一轮播放提交上限 | 24 块，仍受 20 ms 工作预算/SDK 调用返回约束 |
| 已提交音频领先上限 | 480 ms |
| 起播积累目标 | 3840 个 16 kHz PCM 样本，约 240 ms |
| 短句不足阈值的最长等待 | 120 ms |
| 播放轮询 | 5 ms |

编解码器在会话准备时创建，停止采播后、交出 RTC owner 前销毁，归还后续视频通话需要的堆内存；后台预备连接不提前创建编解码器。

AI 工作线程在同一轮中先处理播放，再调用采集接口取得 20 ms、640 字节 PCM；AEC 后端的 SDK 回调提供录音数据，独立工作线程提交播放和处理停流。网络格式与 Lite 一致，收发均使用 `TIRTC_AUDIO_OPUS / TIRTC_AUDIOSAMPLE_16K16B1C`；下行最长 120 ms / 包，解码后按最多 320 样本分块播放，队列暂满时保留剩余 PCM，避免重复解码；硬件约定见 [音频适配](../media/README.md)。

默认 `TIRTC_AUDIO_AEC_EN=y` 使用 F6D_D 3A 连续采播，硬件适配负责启动和播放队列，不再叠加普通录放音的 1200 + 80 ms 静音预热。关闭 AEC 时仍保留原预热策略。具体约定见 [audio_device.h](../media/audio_device.h)，不构成端到端时延保证。

开启 AEC 时，AI 播放期间继续上传麦克风，支持边播边听和云端插话打断，遵循用户关麦与音量设置。关闭 AEC 时保留播放期间抑制上行及尾部保护。

开启 AEC 时，远端结束后保留告别语播放收尾，再退出会话；用户取消或转入通话时按原流程停止。

## AI 呼叫接管

标准命令 `device_action/call_contact` 与有效旧式 `call_intent/ai_call_intent` 进入统一处理：校验 → 请求新联系人刷新票据 → 精确唯一匹配 → 返回受理结果 → 排队 calls → 停止 AI → 取得媒体使用权拨号。

不猜联系人，不因为云端说“正在呼叫”就当作已拨出；显式语音参数不会被默认视频覆盖。取消、来电、断网、解绑使旧请求失效。协议、结果码和示例见主文档，避免在这里重复维护两套配置说明。

## 运行边界

常态保留启动和必要错误，界面中的音频状态与计数继续更新。`[AI-CALL] handoff` 代表已转交通话模块，不代表对端接听。

SDK 的阻塞录音/异步播放退出约束由 media 适配保留，不通过强制删除任务或释放在途缓冲来“快速恢复”。构建、模拟检查和实机效果分别核对，固件用途与构建方式见 [构建与固件](../docs/构建与固件.md)。
