# 电子吧唧设备端交互协议说明

## 1. 文档目的

本文档面向电子吧唧设备端开发人员，说明设备固件需要实现的功能、MQTT 连接方式、设备上报内容、绑定二维码显示、图片任务接收、图片断点续传下载、图片显示与结果上报流程。

本文档中的“设备端”主要指：

- 电子吧唧硬件设备
- 设备固件
- MQTT 客户端
- 屏幕显示程序
- 图片下载程序
- 本地存储与状态管理程序

用户登录、用户鉴权、图片上传、图片裁剪、图片格式转换、任务管理、设备绑定关系管理等逻辑由软件端实现。

设备端重点关注：

```text
设备如何上线
设备如何保持在线
设备如何绑定用户
设备如何接收图片任务
设备如何断点续传下载图片
设备如何显示图片
设备如何上报执行结果
```

------

## 2. 系统角色说明

### 2.1 电子吧唧设备端

电子吧唧设备端负责：

- 获取设备 IMEI
- 连接 MQTT 平台
- 上报设备上线状态
- 定时上报心跳
- 未绑定时显示二维码
- 接收平台下发的图片显示任务
- 支持图片断点续传下载
- 校验图片完整性
- 刷新屏幕显示图片
- 上报任务执行结果
- 处理 MQTT 断线重连、弱网重试等异常情况

### 2.2 软件平台端

软件平台端负责：

- 设备自动注册
- 设备在线状态维护
- 用户登录与鉴权
- 用户与设备绑定
- 图片上传、裁剪、缩放、格式转换
- 图片资源存储
- 图片任务创建
- MQTT 指令下发
- 设备执行结果接收
- H5 任务状态展示

设备端不直接处理用户身份和权限，设备端只执行平台下发的合法任务。

------

## 3. 设备唯一标识

设备唯一标识使用 IMEI。

设备启动后必须获取本机 IMEI，并在以下场景中使用：

- MQTT Client ID
- MQTT username
- MQTT Topic 路径
- 设备上线消息
- 设备心跳消息
- 绑定请求消息
- 图片任务结果上报消息

示例：

```text
imei = 860123456789012
```

MQTT Client ID 建议格式：

```text
badge_{imei}
```

示例：

```text
badge_860123456789012
```

要求：

- IMEI 必须是设备唯一标识
- 所有设备上报消息必须携带 IMEI
- 设备订阅和发布的 Topic 中必须包含 IMEI
- IMEI 只作为设备身份标识，不作为唯一安全凭证

------

## 4. MQTT 连接要求

设备通过 MQTT 与平台保持长连接。

### 4.1 MQTT 连接参数

| 参数          | 建议值               |
| ------------- | -------------------- |
| 协议版本      | MQTT 3.1.1 或 MQTT 5 |
| Client ID     | badge_{imei}         |
| username      | imei                 |
| password      | 平台约定密码或签名   |
| keep alive    | 30 秒                |
| QoS           | 1                    |
| clean session | false 或按平台要求   |
| 传输方式      | TCP 或 TLS           |

### 4.2 MQTT 鉴权说明

基础方案：

```text
username = imei
password = 平台约定的产品密钥或设备签名
```

推荐方案：

```text
username = imei
password = HMAC-SHA256(imei + timestamp + nonce, product_secret)
```

说明：

- IMEI 不建议直接作为密码
- 设备固件中可内置产品级密钥
- 后续如需要更高安全等级，可升级为一机一密

------

## 5. MQTT Topic 设计

### 5.1 设备订阅 Topic

设备上线后需要订阅：

```text
/badge/{imei}/down
/badge/{imei}/cmd
```

示例：

```text
/badge/860123456789012/down
/badge/860123456789012/cmd
```

### 5.2 设备发布 Topic

设备需要向平台发布：

```text
/badge/{imei}/up
/badge/{imei}/status
/badge/{imei}/event
/badge/{imei}/reply
/badge/{imei}/bind
```

示例：

```text
/badge/860123456789012/status
/badge/860123456789012/reply
```

### 5.3 Topic 用途说明

| Topic                  | 方向         | 说明                     |
| ---------------------- | ------------ | ------------------------ |
| `/badge/{imei}/up`     | 设备 -> 平台 | 设备上行通用消息         |
| `/badge/{imei}/status` | 设备 -> 平台 | 设备上线、心跳、状态上报 |
| `/badge/{imei}/event`  | 设备 -> 平台 | 设备事件、下载进度等     |
| `/badge/{imei}/reply`  | 设备 -> 平台 | 设备对平台指令的执行结果 |
| `/badge/{imei}/bind`   | 设备 -> 平台 | 绑定相关状态上报         |
| `/badge/{imei}/down`   | 平台 -> 设备 | 平台下行通用消息         |
| `/badge/{imei}/cmd`    | 平台 -> 设备 | 平台业务指令下发         |

------

## 6. 通用消息格式

设备与平台之间的 MQTT 消息统一使用 JSON 格式。

### 6.1 基础消息格式

```json
{
  "msg_id": "online_001",
  "type": "device.online",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "data": {}
}
```

字段说明：

| 字段      | 类型   | 必填 | 说明        |
| --------- | ------ | ---- | ----------- |
| msg_id    | string | 是   | 消息唯一 ID |
| type      | string | 是   | 消息类型    |
| imei      | string | 是   | 设备 IMEI   |
| timestamp | int64  | 是   | 毫秒时间戳  |
| version   | string | 是   | 协议版本    |
| data      | object | 是   | 业务数据    |

### 6.2 应答消息格式

设备回复平台指令时使用以下格式：

```json
{
  "msg_id": "reply_001",
  "reply_to": "cmd_202606230001",
  "type": "image.display.result",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "code": 0,
  "message": "success",
  "data": {}
}
```

字段说明：

| 字段     | 类型   | 必填 | 说明                      |
| -------- | ------ | ---- | ------------------------- |
| reply_to | string | 是   | 对应平台下发指令的 msg_id |
| code     | int    | 是   | 执行结果码                |
| message  | string | 是   | 执行结果描述              |
| data     | object | 是   | 业务数据                  |

## 7. 设备端状态

设备端需要根据平台返回状态和本地执行状态维护当前状态。

### 7.1 绑定状态

| 状态     | 说明           |
| -------- | -------------- |
| unbound  | 未绑定用户     |
| bound    | 已绑定用户     |
| disabled | 设备被平台禁用 |

### 7.2 屏幕状态

| 状态        | 说明           |
| ----------- | -------------- |
| idle        | 空闲           |
| binding     | 显示绑定二维码 |
| downloading | 正在下载图片   |
| displaying  | 正在显示图片   |
| error       | 异常           |

## 8. 设备上线流程

### 8.1 流程说明

设备启动后，需要完成以下流程：

```text
设备启动
  -> 获取 IMEI
  -> 连接 MQTT
  -> 订阅 /badge/{imei}/down
  -> 订阅 /badge/{imei}/cmd
  -> 上报 device.online
  -> 接收平台 device.init
  -> 根据 bind_status 进入绑定页或正常显示页
```

### 8.2 设备上线消息

Topic：

```text
/badge/{imei}/status
```

消息：

```json
{
  "msg_id": "online_001",
  "type": "device.online",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "data": {
    "firmware_version": "1.0.0",
    "hardware_version": "A1",
    "battery": 86,
    "screen_width": 360,
    "screen_height": 360,
    "screen_color": "rgb",
    "storage_total": 4194304,
    "storage_free": 1048576,
    "network": "4g"
  }
}
```

字段说明：

| 字段             | 说明                     |
| ---------------- | ------------------------ |
| firmware_version | 固件版本                 |
| hardware_version | 硬件版本                 |
| battery          | 电量百分比               |
| screen_width     | 屏幕宽度                 |
| screen_height    | 屏幕高度                 |
| screen_color     | 屏幕色彩类型             |
| storage_total    | 总存储空间，单位 byte    |
| storage_free     | 剩余存储空间，单位 byte  |
| network          | 网络类型，例如 4g / wifi |

### 8.3 接收平台初始化消息

平台会下发：

```json
{
  "msg_id": "server_001",
  "type": "device.init",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "data": {
    "bind_status": "unbound",
    "server_time": 1782211200000,
    "heartbeat_interval": 30,
    "image_max_size": 1048576,
    "supported_image_format": ["rgb565", "jpg", "gif"]
  }
}
```

设备处理逻辑：

| bind_status | 设备行为                       |
| ----------- | ------------------------------ |
| unbound     | 进入二维码绑定页面             |
| bound       | 进入正常显示页面               |
| disabled    | 显示设备禁用状态，停止业务处理 |

## 9. 心跳上报

设备需要定时上报心跳。

建议心跳间隔由平台 `device.init.heartbeat_interval` 下发。
如果平台未下发，默认 30 秒一次。

Topic：

```text
/badge/{imei}/status
```

消息：

```json
{
  "msg_id": "heartbeat_001",
  "type": "device.heartbeat",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "data": {
    "battery": 85,
    "charging": false,
    "rssi": -72,
    "free_memory": 53248,
    "storage_total": 4194304,
    "storage_free": 1048576,
    "screen_status": "idle",
    "current_image_id": "img_202606230001"
  }
}
```

字段说明：

| 字段             | 说明                  |
| ---------------- | --------------------- |
| battery          | 当前电量              |
| charging         | 是否正在充电          |
| rssi             | 信号强度              |
| free_memory      | 剩余内存              |
| storage_total    | 总存储空间，单位 byte |
| storage_free     | 空闲存储空间，单位 byte |
| screen_status    | 当前屏幕状态          |
| current_image_id | 当前显示图片 ID，可选 |

## 10. 设备绑定流程

设备端有屏幕，因此推荐通过二维码完成用户绑定。

### 10.1 绑定整体流程

```text
设备未绑定
  -> 设备请求 bind_token
  -> 平台返回 bind_url
  -> 设备生成二维码
  -> 设备屏幕显示二维码
  -> 用户 H5 扫码绑定
  -> 平台通知设备 bind.success
  -> 设备退出绑定页面
```

### 10.2 请求绑定 Token

设备在未绑定状态下向平台请求绑定 token。

Topic：

```text
/badge/{imei}/up
```

消息：

```json
{
  "msg_id": "bind_req_001",
  "type": "bind.token.request",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "data": {
    "reason": "device_unbound"
  }
}
```

### 10.3 接收绑定 URL

平台返回：

```json
{
  "msg_id": "bind_token_001",
  "type": "bind.token.response",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "data": {
    "bind_token": "8F3K2P",
    "expire_seconds": 300,
    "bind_url": "https://h5.example.com/bind?imei=860123456789012&bind_token=8F3K2P"
  }
}
```

设备需要将 `bind_url` 生成二维码，并显示到屏幕。

二维码内容示例：

```text
https://h5.example.com/bind?imei=860123456789012&bind_token=8F3K2P
```

### 10.4 二维码过期处理

设备需要根据 `expire_seconds` 判断二维码是否过期。

建议处理方式：

```text
二维码即将过期时，重新请求 bind_token。
二维码过期后，屏幕显示“二维码已过期，正在刷新”。
```

建议：

| 项目              | 建议值       |
| ----------------- | ------------ |
| bind_token 有效期 | 300 秒       |
| 重新申请时间      | 过期前 10 秒 |
| 绑定页面状态      | binding      |

### 10.5 绑定成功通知

平台下发：

```json
{
  "msg_id": "bind_success_001",
  "type": "bind.success",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "data": {
    "nickname": "我的电子吧唧",
    "bind_time": 1782211200000
  }
}
```

设备收到后：

```text
1. 退出二维码绑定页面
2. 更新本地绑定状态
3. 进入正常显示页面
```

### 10.6 解绑通知

平台可能下发解绑消息：

```json
{
  "msg_id": "unbind_001",
  "type": "bind.unbind",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "data": {
    "reason": "user_unbind"
  }
}
```

设备收到后：

```text
1. 清除本地绑定状态
2. 进入二维码绑定页面
3. 重新请求 bind_token
```

## 11. 图片显示任务说明

用户在 H5 端选择图片后，平台会处理图片，并通过 MQTT 下发图片显示任务。

设备端不建议处理用户上传的任意原始 JPG、PNG、WebP 图片。
平台会把用户上传的静态图片统一裁剪 / 缩放 / 转换为设备支持的 Baseline Sequential JPEG，把 GIF 动图统一处理为设备屏幕尺寸的 GIF。
设备端当前支持：

```text
RGB565 bin
JPG (Baseline Sequential JPEG)
GIF
```

这样设备端只需要：

```text
下载图片
校验图片
刷新屏幕
上报结果
```

```json
  "imei": "860123456789012",

  "version": "1.0",

    "task_id": "task_202606230001",

```

字段说明：

| 字段           | 类型   | 说明                         |
| -------------- | ------ | ---------------------------- |
| task_id        | string | 图片显示任务 ID              |
| image_id       | string | 图片资源 ID                  |
| image_url      | string | 图片下载地址                 |

```json
  "type": "image.display.accepted",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
```

## 13. 图片断点续传下载要求

设备端下载图片时，必须支持断点续传，以适应弱网、网络抖动、下载中断等场景。

设备不应只支持一次性完整下载。
推荐设备按分片方式下载图片文件，并在下载失败后从已下载位置继续请求剩余数据。

### 13.1 Range 下载方式

设备下载图片时，建议使用 HTTP Range 请求。

首次下载：

```http
GET /device-image/img_202606230001.bin HTTP/1.1
Host: cdn.example.com
Range: bytes=0-4095
```

继续下载：

```http
GET /device-image/img_202606230001.bin HTTP/1.1
Host: cdn.example.com
Range: bytes=4096-8191
```

如果设备已经下载 32768 字节后发生网络中断，恢复后应从 32768 字节继续下载：

```http
GET /device-image/img_202606230001.bin HTTP/1.1
Host: cdn.example.com
Range: bytes=32768-
```

### 13.2 设备本地下载状态

设备下载过程中需要保存当前下载状态。

建议保存：

| 字段            | 说明            |
| --------------- | --------------- |
| task_id         | 当前下载任务 ID |
| image_id        | 当前图片 ID     |
| image_size      | 图片总大小      |
| downloaded_size | 已下载大小      |
| md5             | 图片完整 MD5    |
| temp_file_path  | 临时文件路径    |
| download_status | 下载状态        |

### 13.3 下载流程

```text
收到 image.display
  -> 检查 task_id 是否重复
  -> 检查本地是否存在未完成下载文件
  -> 如果存在，读取 downloaded_size
  -> 使用 Range 从 downloaded_size 位置继续下载
  -> 每次下载成功后更新 downloaded_size
  -> 下载完成后校验 image_size
  -> 校验 MD5
  -> 校验成功后刷新屏幕
  -> 上报 image.display.result
```

### 13.4 下载失败重试策略

建议设备端重试策略：

| 项目             | 建议值                |
| ---------------- | --------------------- |
| 单次请求超时     | 15 秒                 |
| 单片大小         | 4KB 或 8KB            |
| 最大连续失败次数 | 5 次                  |
| 重试间隔         | 2 秒、5 秒、10 秒递增 |
| 总下载超时       | 120 秒                |
| 下载完成校验     | image_size + md5      |

### 13.5 HTTP 状态码处理

设备端需要处理以下 HTTP 状态码：

| 状态码 | 说明                  | 设备处理                             |
| ------ | --------------------- | ------------------------------------ |
| 200    | 完整文件返回          | 可接受，但不适合断点续传             |
| 206    | Partial Content       | 正常断点续传响应                     |
| 416    | Range Not Satisfiable | 本地断点异常，删除临时文件后重新下载 |
| 403    | URL 过期或无权限      | 上报失败                             |
| 404    | 图片不存在            | 上报失败                             |
| 5xx    | 服务端异常            | 重试                                 |

### 13.6 临时文件写入要求

设备下载时应先写入临时文件，不要直接覆盖当前正在显示的图片。

推荐流程：

```text
下载到 image_id.tmp
  -> 下载完成
  -> 校验 image_size
  -> 校验 md5
  -> 校验成功后重命名为 image_id.bin
  -> 刷新屏幕
```

这样可以避免下载失败导致当前显示图片损坏。

## 14. 下载进度上报

设备可以在下载过程中上报进度, H5端就可以显示上传进度条

第一版如果想简单，可以只在以下节点上报：

```text
开始下载
下载 50%
下载完成
下载失败
```

Topic：

```text
/badge/{imei}/event
```

消息：

```json
{
  "msg_id": "progress_001",
  "type": "image.download.progress",
  "imei": "860123456789012",
  "timestamp": 1782211200000,
  "version": "1.0",
  "data": {
    "task_id": "task_202606230001",
    "image_id": "img_202606230001",
    "downloaded": 4096,
    "total": 32768,
    "progress": 12,
    "range_resume": true
  }
}
```

字段说明：

| 字段         | 说明             |
| ------------ | ---------------- |
| task_id      | 当前图片任务 ID  |
| image_id     | 当前图片 ID      |
| downloaded   | 已下载字节数     |
| total        | 总字节数         |
| progress     | 下载百分比       |
| range_resume | 是否使用断点续传 |

## 15. 图片校验要求

设备下载完成后，必须进行完整性校验。

### 15.1 文件大小校验

设备需要校验实际下载文件大小是否等于平台下发的 `image_size`。

如果不一致，设备应删除临时文件并上报失败。

### 15.2 MD5 校验

设备需要计算完整文件 MD5，并与平台下发的 `md5` 字段比较。

如果不一致，设备应删除临时文件并上报失败。

### 15.3 校验失败处理

校验失败后建议处理：

```text
1. 删除临时文件
2. 重新下载一次
3. 如果再次失败，上报 image.display.result 失败
```

------

## 16. 图片显示要求

图片下载并校验成功后，设备刷新屏幕显示图片。

设备处理流程：

```text
1. 下载图片
2. 校验 image_size
3. 校验 md5
4. 判断 image_format 是否支持
5. 写入屏幕缓存
6. 刷新屏幕
7. 保存 current_image_id
8. 上报 image.display.result
```

### 16.1 图片格式要求

当前设备需要支持平台下发的格式：

```text
rgb565
jpg
gif
```

其中 `jpg` 为 Baseline Sequential JPEG 编码，平台会把非 GIF 用户上传图片统一裁剪 / 缩放 / 转换为 360x360 JPG。
平台会把 GIF 动图统一裁剪 / 缩放 / 转换为 360x360 GIF。
设备端不需要处理用户上传的原始：

```text
png
webp
```

这些格式应由软件端统一转换成设备可直接显示的格式。

## 19. 重复任务处理

由于 MQTT QoS 1 可能出现重复消息，设备必须做任务去重。

去重依据：

```text
task_id
```

处理规则：

```text
如果 task_id 已成功执行过，不重复执行。
如果 task_id 正在执行中，不重复下载。
如果 task_id 执行失败，可按设备策略决定是否重新执行。
```

设备本地建议保存：

| 字段              | 说明                |
| ----------------- | ------------------- |
| last_task_id      | 最近执行任务 ID     |
| current_task_id   | 当前正在执行任务 ID |
| current_image_id  | 当前显示图片 ID     |
| current_image_md5 | 当前图片 MD5        |
| last_display_time | 最近显示时间        |

## 20. MQTT 断线与弱网处理

设备必须支持 MQTT 自动重连。

建议策略：

| 场景             | 设备处理                                       |
| ---------------- | ---------------------------------------------- |
| MQTT 断开        | 自动重连                                       |
| MQTT 重连成功    | 重新订阅下行 Topic                             |
| 设备重新上线     | 重新上报 device.online                         |
| 下载中 MQTT 断开 | 图片下载可继续执行，但结果需待 MQTT 恢复后上报 |
| 下载中网络断开   | 保留 downloaded_size，网络恢复后断点续传       |

------

## 21. 设备端本地存储要求

设备本地需要保存少量状态。

建议保存：

| 数据            | 是否必须 | 说明                 |
| --------------- | -------- | -------------------- |
| 当前显示图片    | 必须     | 设备重启后可恢复显示 |
| 当前 image_id   | 建议     | 方便上报状态         |
| 当前图片 MD5    | 建议     | 方便校验             |
| 最近 task_id    | 建议     | 防止重复执行         |
| 下载临时文件    | 必须     | 支持断点续传         |
| downloaded_size | 必须     | 支持断点续传         |
| MQTT 配置       | 必须     | 平台地址、端口等     |

绑定关系建议以平台为准。
设备可以缓存绑定状态，但不能完全依赖本地缓存。

设备每次上线后，应以平台返回的 `device.init.bind_status` 为准。

------

## 22. 设备异常处理

| 异常            | 设备处理方式                 |
| --------------- | ---------------------------- |
| MQTT 断开       | 自动重连                     |
| 网络不可用      | 定时重试                     |
| bind_token 过期 | 重新申请                     |
| 图片下载失败    | 断点续传重试，失败后上报     |
| 图片大小不匹配  | 删除临时文件并上报失败       |
| MD5 校验失败    | 删除临时文件并上报失败       |
| 图片格式不支持  | 上报失败                     |
| 屏幕刷新失败    | 上报失败                     |
| 存储空间不足    | 清理旧图片或上报失败         |
| URL 过期        | 上报失败，等待平台重新下发   |
| Range 不支持    | 可退化为完整下载，或上报失败 |

## 24. 设备端第一版必须实现清单

第一版设备端必须实现：

- 获取 IMEI
- MQTT 连接
- MQTT 自动重连
- 订阅 `/badge/{imei}/down`
- 订阅 `/badge/{imei}/cmd`
- 上报 `device.online`
- 上报 `device.heartbeat`
- 请求 `bind_token`
- 显示绑定二维码
- 接收 `bind.success`
- 接收 `image.display`
- 回复 `image.display.accepted`
- 支持 HTTP Range 断点续传下载图片
- 保存 downloaded_size
- 下载失败后从断点继续下载
- 校验图片大小
- 校验图片 MD5
- 刷新屏幕显示图片
- 上报 `image.display.result`
- 根据 `task_id` 做重复任务过滤

## 26. 设备端最小闭环

```text
设备开机
  -> 获取 IMEI
  -> 连接 MQTT
  -> 订阅下行 Topic
  -> 上报 device.online
  -> 接收平台 device.init
  -> 未绑定则请求 bind_token
  -> 显示绑定二维码
  -> 用户扫码绑定
  -> 设备收到 bind.success
  -> 接收 image.display 图片任务
  -> 回复 image.display.accepted
  -> 使用 HTTP Range 下载图片
  -> 弱网中断后断点续传
  -> 校验 image_size
  -> 校验 MD5
  -> 刷新屏幕显示图片
  -> 上报 image.display.result
```
